# Product service

Standalone Spring Boot catalog demo with PostgreSQL storage. Requires Java 17+, Maven 3.9+, and Docker Compose.

## Run

From `project/product-service`:

```sh
docker compose up -d postgres
mvn spring-boot:run
```

HTTP defaults to port 8082. PostgreSQL defaults to `jdbc:postgresql://localhost:5434/products` with demo user/password `products`. Override `PORT`, `DB_URL`, `DB_USERNAME`, and `DB_PASSWORD` as needed. The database port avoids the order and auth services. Hibernate updates the demo schema automatically.

## API

```sh
curl -i http://localhost:8082/products \
  -H 'Content-Type: application/json' \
  -d '{"name":"Keyboard","price":19.99}'
curl -i http://localhost:8082/products/1
curl -i http://localhost:8082/products
```

- `POST /products`: returns 201 Created, `Location: http://localhost:8082/products/1`, and `{"id":1,"name":"Keyboard","price":19.99}`. IDs are generated by the database.
- `GET /products/{id}`: returns 200 with the stored product, or 404 if absent. An invalid numeric ID returns 400.
- `GET /products`: returns 200 with an array ordered by ascending ID; an empty catalog returns `[]`.

Name is required, nonblank, and limited to 255 characters. Price is required, nonnegative (zero is allowed), and limited to 10 integer digits and 2 decimal places. Invalid requests return 400. Prices use decimal arithmetic and are stored as NUMERIC(12,2); this demo assumes a single currency.

## Verify

```sh
mvn verify
```

Integration tests use H2 without Docker and exercise persistence, reads, and invalid inputs. The packaged service was also checked over HTTP against PostgreSQL 16 for creation, decimal persistence, lookup, ordered listing, and error responses.

This is a local interview demo: no authentication, pagination, update/delete endpoints, inventory, or order-service integration. Use access control, migrations instead of Hibernate schema update, and proper credentials before deploying. The Compose database has no named volume; deleting its container removes its data.
